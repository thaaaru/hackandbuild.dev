1. Introduction to Linux for Cybersecurity

Why Linux Matters in Security

  • Most servers run Linux (90%+ of web servers)
  • Penetration testing tools are Linux-native
  • Forensic analysis often requires Linux
  • Cloud infrastructure is Linux-based
  • Open source = transparent security

Linux Distributions for Security

  • Kali Linux - Penetration testing
  • Parrot Security - Digital forensics
  • Ubuntu - General purpose
  • CentOS/RHEL - Enterprise servers
  • Arch Linux - Custom builds

Linux vs Windows in Security

Linux Advantages: • User privilege separation • Package management • Open source transparency • Minimal attack surface • Command-line efficiency Windows Advantages: • GUI familiarity • Enterprise integration • Commercial support

🔒 Security Context

Real-world scenario: A security analyst needs to analyze a compromised server. The server runs Linux, and most forensic tools (Volatility, Autopsy, etc.) are Linux-based. Understanding Linux is crucial for effective incident response and digital forensics.

2. Linux Filesystem Deep Dive

Filesystem Hierarchy Standard (FHS)

/ (root) ├── /bin - Essential binaries ├── /etc - Configuration files ├── /home - User directories ├── /var - Variable data ├── /tmp - Temporary files ├── /usr - User programs └── /opt - Optional software

Critical Security Directories

  • /etc/passwd - User accounts
  • /etc/shadow - Password hashes
  • /etc/ssh/ - SSH configuration
  • /var/log/ - System logs
  • /proc/ - Process information

Navigation Commands

# Basic navigation pwd # Print working directory ls -la # List files with details cd /path/to/directory # Change directory cd ~ # Go to home directory cd .. # Go up one level # Finding files find / -name "filename" 2>/dev/null locate filename which command_name

🔒 Security Context

Incident Response: During a security breach, analysts must quickly navigate the filesystem to locate malicious files, check system logs, and understand the attack vector. Knowledge of critical directories like /var/log/ and /etc/ is essential for effective forensics.

3. Essential Linux Commands for Daily Use

File Operations

# File manipulation cp source destination # Copy files mv old_name new_name # Move/rename files rm filename # Remove files mkdir directory_name # Create directory rmdir directory_name # Remove empty directory # File viewing cat filename # Display file content less filename # Page through file head -n 10 filename # First 10 lines tail -n 10 filename # Last 10 lines

Text Processing

# Text manipulation grep "pattern" file # Search for pattern grep -r "pattern" /dir # Recursive search awk '{print $1}' file # Print first column sed 's/old/new/g' file # Replace text sort file # Sort lines uniq file # Remove duplicates

System Information

# System monitoring ps aux # Running processes top # Real-time processes htop # Enhanced process viewer df -h # Disk usage free -h # Memory usage uname -a # System information whoami # Current user id # User/group IDs

🔒 Security Context

Threat Hunting: Security analysts use commands like ps aux to identify suspicious processes, grep to search through logs for indicators of compromise, and netstat to detect unusual network connections during threat hunting activities.

4. Managing Users and Groups

User Management Commands

# User operations sudo useradd username # Create user sudo userdel username # Delete user sudo usermod -aG group user # Add user to group sudo passwd username # Change password id username # Show user info who # Show logged in users last # Show login history

Group Management

# Group operations sudo groupadd groupname # Create group sudo groupdel groupname # Delete group groups username # Show user groups sudo gpasswd -a user group # Add user to group sudo gpasswd -d user group # Remove user from group

Important Files

  • /etc/passwd - User account information
  • /etc/shadow - Encrypted passwords
  • /etc/group - Group information
  • /etc/sudoers - Sudo permissions

🔒 Security Context

Access Control: In enterprise environments, proper user and group management is critical for implementing the principle of least privilege. Security teams must regularly audit user accounts, remove inactive users, and ensure appropriate group memberships to prevent unauthorized access.

5. File Permissions and Ownership

Understanding Permissions

# Permission structure -rwxrwxrwx - rwx rwx rwx | | | | | | | └── Other (o) | | └────── Group (g) | └────────── Owner (u) └────────────── File type (- = file, d = directory)

Permission Commands

# Change permissions chmod 755 filename # rwxr-xr-x chmod u+x filename # Add execute for owner chmod g-w filename # Remove write for group chmod o-r filename # Remove read for others # Change ownership sudo chown user:group filename # Change owner and group sudo chown user filename # Change owner only sudo chgrp group filename # Change group only

Common Permission Values

# Numeric permissions 7 = rwx (read, write, execute) 6 = rw- (read, write) 5 = r-x (read, execute) 4 = r-- (read only) 3 = -wx (write, execute) 2 = -w- (write only) 1 = --x (execute only) 0 = --- (no permissions) # Common combinations 755 = rwxr-xr-x (executable files) 644 = rw-r--r-- (regular files) 700 = rwx------ (private files)

Special Permissions

# Setuid, Setgid, Sticky bit chmod u+s filename # Setuid (run as owner) chmod g+s filename # Setgid (run as group) chmod +t directory # Sticky bit (only owner can delete) # Examples -rwsr-xr-x # Setuid executable -rwxr-sr-x # Setgid executable drwxrwxrwt # Sticky bit directory

🔒 Security Context

Privilege Escalation: Attackers often exploit misconfigured file permissions to escalate privileges. Security professionals must understand how to properly set permissions, identify dangerous setuid/setgid binaries, and audit file ownership to prevent unauthorized access to sensitive files.
